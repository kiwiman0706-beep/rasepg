# 構成の考察（設計判断とおすすめ）

元の仕様書は「Pi4 + PX-Q1UD + Mirakurun + EPGStation + Docker + NAS(SMB)」という、
日本の DTV 録画で最も実績のある王道スタックで、基本方針は妥当です。
そのうえで、実運用で効いてくるポイントを技術的に見直し、いくつか変更・強化しました。

結論だけ先に:

| 項目 | 元仕様 | 本プロジェクトの採用 | 理由 |
|---|---|---|---|
| チューナー制御 | recpt1 前提 | **recdvb + メインライン DVB(smsdvb)** | PX-Q1UD は Siano 系の DVB 準拠機。専用ドライバ不要で安定 |
| 一時保存先 | microSD or SSD | **外付け SSD/HDD（USB3）を強く推奨・既定** | SD は書込寿命・速度がボトルネック |
| エンコード | HW(h264_v4l2m2m) 固定 | **HW 既定＋SW(x264) を Web から切替可** | Pi4 の HW エンコーダは画質が弱い。用途で選べるように |
| 管理操作 | （記載なし） | **専用 Web 管理パネル（保存先/NAS/WiFi/サービス）** | 「Web だけで完結」を満たすための追加コンポーネント |
| イメージ配布 | （手作業想定） | **pi-gen + GitHub Actions で .img を自動ビルド** | 再現性・更新のしやすさ |

---

## 1. チューナー：PX-Q1UD は「DVB 準拠機」

PX-Q1UD は PX-S1UD（Siano SMS2270 系）を 4 つ束ねた地デジ専用機で、
**Linux メインラインの `smsdvb` ドライバ＋Siano ファームウェア（`isdbt_nova_12mhz_b0.inp`）だけで
4 つの DVB アダプタとして認識**できます。PLEX PX4/PX5 系の `px4_drv` のような
out-of-tree ドライバのビルドは不要です（=カーネル更新で壊れにくい）。

そのため録画コマンドは `recpt1` ではなく **DVB 版の `recdvb`** を採用します。
B-CAS 解除は `recdvb --b25`（libarib25 + pcscd 経由の B-CAS 1 枚共有）で行います。

> 注意: TS のスクランブル解除（いわゆる「TS 抜き」）は、B-CAS カードと
> arib25 を用いる個人利用の一般的手法ですが、取り扱いはご自身の責任と
> 適用法令の範囲で行ってください。本リポジトリは録画サーバ基盤（OSS 構成）を提供するものです。

## 2. ストレージ：一時保存に microSD は使わない

- HD の TS はおよそ **7〜8GB/時**。SD への連続書込は寿命・速度の両面で不利で、
  4ch 同時録画では SD の書込帯域が詰まって取りこぼしの原因になります。
- **USB3 接続の SSD（または HDD）を一時保存領域（録画→エンコード作業用）に**、
  最終保存は **NAS(SMB)** という二段構成を既定にします。
- 保存先（一時/最終）とマウントは **Web 管理パネルから設定**できます（fstab を自動生成）。

## 3. エンコード：HW を既定にしつつ、質重視は SW を選べるように

Pi4 には V4L2 M2M の H.264 ハードエンコーダ（`h264_v4l2m2m`）があります。

- **HW(h264_v4l2m2m)**: ほぼ実時間で軽い。ただし B フレーム無し・レート制御が単純で、
  同ビットレートでの画質は x264 に劣る。1080i はソフトでデインターレース（bwdif）してから投入。
  → **宅外視聴向けの軽量 MP4（720p / 約2Mbps）にちょうど良い。既定。**
- **SW(x264 veryfast)**: 画質は明確に上。Pi4 では 1080i→720p でおよそ実時間の 0.5〜0.8 倍
  （録画より遅い）だが、エンコードは録画後のキュー処理なので許容できることが多い。
  → **保存重視/画質重視のときに Web から選択。**

### 代替案（ハード選定の指針）

- **Raspberry Pi 5 を使う場合**: Pi5 は H.264 ハードエンコーダを**廃止**しています。
  ただし CPU が 2〜3 倍速いので **x264 ソフトエンコードが実用的**（Pi4 の HW より速く高画質なことも）。
  「HW エンコードが必須」なら Pi4、「画質優先で 1 台完結」なら Pi5+SW という住み分け。
- **エンコードを Pi でしない案**: TS のまま NAS へ置き、視聴時に
  **Synology / Jellyfin / Emby でオンデマンド transcode**。事前エンコード不要で画質も保てるが、
  保存容量が大きく、宅外回線とサーバ負荷に依存。→ 容量に余裕があるなら有力。

本プロジェクトは「Pi4 + 事前エンコードで軽量 MP4 を NAS へ」という元仕様を既定にしつつ、
上記を選べる/移行できる構造にしています。

## 4. 「Web だけで完結」を満たすための追加

EPGStation は録画予約・番組表・視聴の Web UI を提供しますが、
**NAS マウント・保存先・WiFi・タイムゾーン・サービス起動停止**はふつう CLI 作業です。
これを無くすため、本リポジトリは **専用の Web 管理パネル（RASEPG Admin）** を同梱します。

RASEPG Admin（ホストの systemd サービスとして動作）でできること:

- 一時保存デバイスの選択 / フォーマット確認 / マウント
- NAS(SMB) 接続情報の登録・マウント（fstab 自動生成、認証情報は 0600 で保存）
- エンコードプロファイル（HW/SW/画質）の切替
- Docker サービス（Mirakurun / EPGStation）の起動・停止・再起動・ログ確認
- チューナー / B-CAS / ディスク / 温度などのステータス表示
- WiFi・ホスト名・タイムゾーンの設定
- チャンネルスキャン実行

> 設計上、Admin パネルは**コンテナではなくホスト側 systemd**で動かします。
> マウント・fstab・nmcli・docker 制御などホスト権限が要る操作を安全に扱うためです。

## 5. 信頼性・運用

- **冷却必須**: 4ch 録画＋エンコードは発熱大。ヒートシンク＋ファン付きケース推奨。
- **電源**: PX-Q1UD は付属 AC アダプタ使用（Pi の USB からは給電しない）。SSD は USB3 直結 or セルフパワー。
- **ログローテート / 自動再起動**: コンテナは `restart: unless-stopped`。tuner ハング時の復帰も考慮。
- **時刻同期**: EPG のため NTP 有効（既定で有効）。

## 6. 全体データフロー

```
[地デジ電波] → PX-Q1UD(4tuner) --USB--> Pi4
                        │  (smsdvb + Sianoファーム)
                B-CAS 1枚 ──(pcscd)── recdvb --b25 (arib25で解除)
                        ▼
                 Mirakurun (チューナー制御/配信)
                        ▼
                 EPGStation (予約/番組表/録画)  → 一時保存: 外付けSSD(.ts)
                        │ recordedEnd フック
                        ▼
                 FFmpeg エンコード (HW or SW) → .mp4
                        ▼
                 NAS(SMB) へ移動  → Synology DS Video / VLC 等で視聴

         すべての設定は  RASEPG Admin (Web) ＋ EPGStation (Web) から
```
